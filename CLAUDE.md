# CLAUDE.md

Интернет-магазин цветов, 2 точки. Django + HTMX, Pydantic, PostgreSQL, Redis, Celery.

## Источники истины

- `@tech.md` — ядро проекта. Стек, схема БД, контракты HTTP и Celery, машина статусов, правила кода, безопасность, тест-доктрина. **Подчиняйся дословно.**
- `@DEV.md` — рабочий файл: стадии, слайсы, критерии приёмки, тест-сценарии, чек-лист саморевью.

Читай оба перед первым действием в сессии. Расхождение между кодом и `tech.md` трактуется в пользу `tech.md`.

## Главное правило

Контракты не выдумывай. Модель, поле, эндпоинт, payload задачи, статус, имя UI-примитива — только из `tech.md`.

Нужного контракта там нет — **СТОП**. Выдай блок `CONTRACT GAP` по форме из `DEV.md` §1, работай на локальной заглушке, код с выдуманным типом не пиши. Правка ядра — отдельный коммит с бампом версии, никогда в одном PR с фичей.

## Рабочий режим

- Одна задача за раз, один слайс = один PR, сфокусированный дифф.
- Слайс вертикальный: `domain.py` → `repositories.py` → `services.py` → `views.py` → шаблон → тесты.
- Эталон структуры — `apps/stores` (слайс S0.9). Свою раскладку не изобретай.
- Тесты пишутся из критериев приёмки в `DEV.md`, не из реализации.
- Перед PR пройди чек-лист `DEV.md` §3 механически, по пунктам.

## Красные линии (нарушение = переделка)

- View не импортирует ORM-модели и не содержит бизнес-логики.
- `apps/*/domain.py` не импортирует `django.*`.
- Деньги — `Decimal`, никогда `float`.
- `order.status` меняется только через `orders.services.transition_order`.
- Celery-задачи публикуются через `transaction.on_commit` и идемпотентны.
- Цена, `subtotal` и `total` с клиента не принимаются никогда.
- Телефон, адрес и текст открытки не попадают в логи и в Sentry.
- Внешние сервисы — только через ABC + фейк. Прямой HTTP-вызов из сервиса запрещён.
- Своя вёрстка кнопок и инпутов вместо `templates/ui/` запрещена.
- Секреты камеры (RTSP-URL, логин, пароль) в БД, фикстурах и ответах API не появляются никогда. Только `source_ref`.
- Состояние камеры считает `live.domain.resolve_state`, не шаблон и не view. Пустого чёрного прямоугольника без объяснения не существует.
- Аудио в трансляции нет и не будет — см. `tech.md` §10.8.

## Команды

```bash
docker compose up -d              # web, postgres, redis, celery×4, beat
python scripts/seed.py            # идемпотентный сид
pytest                            # unit + integration + contract
pytest tests/e2e --headed         # Playwright
ruff check . && ruff format --check .
mypy apps
python manage.py makemigrations --check --dry-run
python manage.py check --deploy
bandit -r apps && pip-audit
```

## Конвенция коммитов

`type(scope): summary` — Conventional Commits, английский, императив, до ~50 символов.
`type` ∈ `feat|fix|test|refactor|chore|docs|perf`. `scope` — имя приложения.
Коммиты маленькие и по ходу работы, не один большой в конце.
Правка ядра: `chore(core): bump tech.md to vN`.

## Стиль текста

Сухо, технично, конкретно. Активный залог, императив. Без вводных оборотов, без воды, без эмодзи. Комментарии объясняют *почему*, а не пересказывают код.
