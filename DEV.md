# DEV.md — рабочий файл разработчика (соло-режим)

Проект: сайт цветочной мастерской. Ядро: `tech.md` **v2**.

## Прочитай первым

1. `tech.md` — источник истины. Подчиняйся дословно. `CLAUDE.md` импортирует его в сессию; если работаешь в веб-чате — прикладывай руками.
2. Контракты не выдумывай. Нет нужного поля, задачи, URL или компонента в `tech.md` — выдай блок `CONTRACT GAP` (форма в разделе 21 ядра) и остановись.
3. Одна задача за раз, сфокусированный дифф, один слайс — один PR.
4. Задачи идут по порядку внутри стадии. Стадия 1 не начинается, пока чек-лист «скелет готов» не зелёный целиком.
5. Эталон структуры — слайс `S0-10`. Твой слайс повторяет его раскладку: модель → сервис → вью → шаблон → тесты.

## Роль в соло-режиме

Ты и лид, и разработчик. Разделение сохраняется как разделение **режимов**, не людей.

**Режим лида** — стадия 0 и любое изменение контракта: правишь `tech.md` и бампаешь версию, трогаешь `config/`, `templates/base.html`, `templates/layout/`, `templates/ui/`, `tailwind.config.js`, `clients/`, настраиваешь CI и деплой.

**Режим разработчика** — стадии 1–4: пишешь слайсы, не трогая перечисленное. Упёрся в общий файл — переключаешься отдельным коммитом с явной причиной и возвращаешься.

Смысл: не смешивать в одном PR «сделал фичу» и «поменял общий контракт».

## Миграции

Миграции создаются внутри слайса, но **отдельным коммитом** `chore(<app>): add migration for <что>`, и просматриваются построчно перед мёрджем. Автосгенерированную миграцию не мёрджить не читая: Django умеет молча предложить удаление поля.

## Саморевью PR

Механически, по пунктам, не на глаз.

- [ ] нет выдуманных типов и полей, всё из `tech.md`
- [ ] общие файлы не тронуты, либо тронуты отдельным коммитом с причиной
- [ ] миграция вынесена отдельным коммитом и прочитана глазами
- [ ] тесты выведены из критериев приёмки, а не из реализации
- [ ] использованы примитивы раздела 12 ядра
- [ ] на каждую задачу Celery есть тест идемпотентности
- [ ] на стыке слайса есть контрактный тест
- [ ] `assertNumQueries` на страницах со списками
- [ ] проверено на 360px и 1440px
- [ ] Definition of Done (раздел 20 ядра) пройден целиком

## Рабочий цикл

Ветка `feat/S1-4-gallery-filters` → маленькие коммиты по ходу → PR с ID задачи → зелёный CI → саморевью → squash-мёрдж в `main` → автодеплой на тестовый сервер.

# Стадия 0 — скелет

## S0-1 · Репозиторий и окружение

**Цель.** Проект поднимается одной командой на чистой машине.

**Контракты.** Разделы 2, 3 ядра.

**Делаешь.** Инициализация репозитория; `pyproject.toml` с зависимостями и настройками `ruff`, `mypy`, `pytest`; `Dockerfile` (multi-stage, non-root, бинарник Tailwind CLI внутрь образа); `compose.yaml` с `web`, `db`, `redis`, `celery`, `celery-beat`; `.env.example` со всеми ключами раздела 6 ядра; `Makefile` с `up`, `down`, `test`, `lint`, `migrate`, `seed`, `shell`.

**Критерии приёмки.**

- `cp .env.example .env && docker compose up` поднимает всё без единого реального секрета.
- `make test` проходит на пустом проекте.
- Контейнер `web` не запускается от root.
- Тома: `postgres_data`, `redis_data`, `media_public`, `media_private`.
- В образе нет Node.js: Tailwind собирается standalone-бинарником.

**Тесты.** Смоук: `pytest` находит конфигурацию и завершается успешно на нуле тестов.

## S0-2 · Django-проект, конфиг, хранилища

**Цель.** Конфигурация валидируется на старте, оригиналы фото недоступны публично.

**Контракты.** Раздел 6 ядра целиком.

**Делаешь.** `config/settings_schema.py` с классом `Settings`, включая `field_validator` для `allowed_hosts`, `time_zone`, `use_tz`; `config/settings.py`; `config/storages.py` с `public_storage` и `private_storage`; приложения `core`, `catalog`, `leads`, `reviews`, `blog`; `apps/core/exceptions.py` с `TransientError`; `apps/core/contracts.py` с `EmptyPayload`; подключение `django-unfold`.

**Критерии приёмки.**

- Отсутствие обязательной переменной роняет процесс с внятным сообщением.
- `ALLOWED_HOSTS=a.com, b.com` разбирается корректно; JSON-формат тоже принимается.
- `TIME_ZONE = "Europe/Kyiv"`, `USE_TZ = True`.
- `grep -r "os.environ\|os.getenv" apps/ config/` находит только `settings_schema.py`.
- В проде включены `SECURE_HSTS_SECONDS`, `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE`, `SECURE_SSL_REDIRECT`, `X_FRAME_OPTIONS=DENY`.
- Файл, сохранённый в `private_storage`, не отдаётся по HTTP.

**Тесты.** Валидация `Settings` падает на неполном наборе. **Property-based:** `allowed_hosts` разбирается из строки с любым количеством пробелов и пустых элементов.

## S0-5 · Базовый layout

**Цель.** Каркас, который дальше только наполняется.

**Контракты.** Разделы 4.7, 10 (шапка, баннер, режим приёма заказов), 11 ядра.

**Делаешь.** `templates/base.html` с блоками; `layout/header.html` (липкая шапка, логотип, меню, переключатель языка, телефон, соцсети); `layout/mobile_menu.html` (кнопка с тремя полосками, панель на Alpine); `layout/footer.html`; `layout/banner.html`; `core/navigation.py` с пунктами меню **данными**; `i18n_patterns` с `prefix_default_language=False`; миксин `TranslatedMixin`, фильтры `tr` и `tr_html`; подключение HTMX и Alpine локальными файлами.

**Критерии приёмки.**

- Меню на мобильном скрыто за кнопкой с тремя полосками; логотип, иконка телефона и кнопка меню видны всегда.
- Панель закрывается по Esc, кликом вне и выбором пункта; фон не скроллится при открытой панели.

**Тесты.** Переключение языка с `/galereya/?color=bilyi` ведёт на `/ru/galereya/?color=bilyi`. **Property-based:** построение альтернативного URL сохраняет query при любом наборе параметров. Тест фолбэка `tr()` при пустом русском поле. Тест: `tr` экранирует HTML, `tr_html` — нет.

## S0-6 · UI-примитивы и kitchen-sink

**Цель.** Все примитивы раздела 12 ядра существуют до начала фич.

**Контракты.** Раздел 12 ядра целиком.

# Стадия 1 — каталог и галерея

## S1-1 · Модели каталога

**Цель.** Схема данных разделов 4.1–4.6 ядра в базе.

**Контракты.** Разделы 4.1–4.6, 5, 11 ядра. Ни одного поля сверх перечисленных.

**Делаешь.** `Occasion`, `TagGroup`, `Tag`, `Work`, `WorkImage`, `WorkImageRendition`; миграцию с `CREATE SEQUENCE work_article_seq START WITH 100`; выдачу артикула в `save()`; генерацию слага **один раз** при первом сохранении; менеджер `published`; все индексы и ограничения; дополнение сида поводами, группами тегов и работами.

**Критерии приёмки.**

- Первая работа получает артикул 100, следующая 101.
- Артикул и слаг не меняются при редактировании заголовка.
- Работа без заголовка получает слаг вида `147`.
- Два главных фото у одной работы отклоняются ограничением БД.
- `price_to < price_from` отклоняется ограничением.
- `rating` вне 1..5 у отзыва отклоняется (проверяется в стадии 3, ограничение закладывается тогда же).
- Тег со слагом `color` или `sort` отклоняется валидацией.
- `tr()` возвращает русский на `/ru/`, украинский при пустом русском.
- Черновики не всплывают наверх в списках из-за `NULL` в `published_at`.

**Тесты.** **Property-based:** генерация слага даёт уникальный ASCII-слаг для любых кириллических заголовков, включая пустой, эмодзи, строку из пробелов и заголовок длиной 200 символов (проверка усечения до 180). Тест: два последовательных `nextval` дают разные значения, откат транзакции номер не возвращает. Тесты всех ограничений БД. Тест валидации слага тега против зарезервированных имён. Тест сортировки: черновик с `published_at=NULL` не оказывается первым.

## S1-2 · Админка каталога

**Цель.** Владелец добавляет работу с несколькими фотографиями за минуту, в том числе с телефона.

**Контракты.** Разделы 4.4 (правило публикации), 4.5 ядра.

**Делаешь.** `WorkAdmin` на `django-unfold`: список с миниатюрой, артикулом, статусом, поводами, просмотрами; фильтры по статусу, поводам, тегам; поиск по артикулу и заголовку; действия «опубликовать», «в архів», «закріпити». `WorkImageInline` с добавлением фотографий и сортировкой перетаскиванием через `django-admin-sortable2`. Валидацию «у опубликованной работы минимум одна фотография» **в `clean()` формсета инлайна и в `save_related`**, не в `Work.clean()`. Раскладку формы по группам: контент, теги, цены, публикация. Поле `cost` в свёрнутой группе с подписью «внутрішнє, на сайті не показується». Админки `Occasion`, `TagGroup`, `Tag` с сортировкой перетаскиванием.

**Критерии приёмки.**

- Три фотографии, добавленные в инлайне, получают `order` 0, 1, 2 и ровно один `is_main`.
- Первая добавленная фотография автоматически становится главной.
- Удаление главной фотографии делает главной первую по `order`.
- Публикация работы без фотографий отклоняется с понятным сообщением; при создании работы сразу со статусом `published` и приложенными фото сохранение проходит.
- Порядок фотографий меняется перетаскиванием и сохраняется.
- Форма удобна на экране 360px: поля не выходят за границы, кнопка сохранения доступна.
- Значение `cost` не попадает ни в один публичный контекст.

**Тесты.** Тест назначения `order` и `is_main`. Тест переназначения главной при удалении. Тест: сохранение опубликованной работы без фото отклоняется формсетом, с фото — проходит. Тест: рендер карточки работы не содержит значения `cost` ни при каких настройках.

## S1-3 · Изображения: рендишены и водяной знак

**Цель.** Галерея грузится быстро, оригиналы не публикуются.

**Контракты.** Разделы 4.5, 4.6, 8.2, 8.4, 14.1, 14.3 ядра.

**Критерии приёмки.**

**Тесты.** **Идемпотентность:** двойной запуск с одним payload даёт один комплект рендишенов, `renditions_version` не меняется. Тест `force=True`. Тест: изменение `PRESETS_VERSION` вызывает перегенерацию. Тест: имя файла рендишена содержит версию и меняется после перегенерации. Контрактный: `work_image_id=0` отклоняется валидацией. **Критерии приёмки.** Пост открывается на обоих языках с фолбэком. Черновик — 404. Связанные работы кликабельны. Обложка сжимается один раз. Просмотры постов сливаются из Redis.

**Тесты.** Вью-тесты 200 и 404. `assertNumQueries` на списке. Тест: `flush_view_counters` обрабатывает и `views:work:*`, и `views:post:*`, идемпотентность сохраняется.

## S3-5 · Страницы ошибок и юридический блок

**Контракты.** Раздел 10 («Страницы ошибок»), раздел 9 (`/polityka-konfidentsiynosti/`) ядра.

**Делаешь.** Наполнение политики конфиденциальности; кастомные `404.html`, `410.html`, `500.html`.

**Критерии приёмки.** 404 содержит кнопку в галерею и строку поиска по номеру. 410 содержит блок похожих работ. **500 рендерится без обращения к базе**: не наследует `base.html`, не использует контекст-процессоры, стили инлайном. Ссылка на политику есть в подвале, в форме заявки и в cookie-баннере.

**Тесты.** Вью-тесты 404, 410, 500. Тест: рендер `500.html` при недоступной базе не бросает исключение.

# Стадия 4 — прод

## S4-1 · SEO-разметка

**Контракты.** Разделы 9 и 16 ядра.

## S4-2 · Кэш галереи и скорость

**Контракты.** Раздел 14.4 ядра.

**Делаешь.** Кэш фрагментов галереи с версионным ключом `gallery:ver`; инкремент версии в `post_save` и `post_delete` для `Work`, `WorkImage`, `Tag`, `Occasion`; `Cache-Control` на медиа; сжатие статики; замер Lighthouse.

## S4-3 · Продакшен-развёртывание

**Делаешь.** `compose.prod.yaml`; gunicorn; `deploy/nginx.conf` с раздачей `media-public` и статики, **без раздачи `media-private`**; TLS через Cloudflare; workflow деплоя на мёрдж в `main` с миграциями отдельным шагом до перезапуска; `collectstatic` и компиляцию переводов в образ.

**Критерии приёмки.** Мёрдж в `main` доводит изменения до сервера без ручных шагов. Миграции применяются до перезапуска. Откат на предыдущий образ — одна команда. Прямой запрос к пути приватного тома возвращает 404. Секретов в репозитории нет.

**Тесты.** Смоук после деплоя: главная 200, `/admin/` 302, sitemap валиден, приватный путь 404.
